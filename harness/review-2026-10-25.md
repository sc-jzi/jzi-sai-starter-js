# Harness review — 2026-10-25

Scope: the demo pipeline as an *agent harness* — skills (instructions), scripts (tools), gates and hooks (verification and control loop), always-on context, and repo hygiene.
Method: four independent read-only reviews (skills, scripts, gates red-team, context/hygiene), then spot-verification. **V** = verified in this session, **R** = reported by a reviewer with file:line evidence, not independently re-checked.

## The short version

The harness has good bones — measured references, a stop-hook control loop, numeric looks gates, provenance from Sitecore/Edge in the newer checks — but three structural problems keep producing the failures you have been seeing:

1. **The gate still trusts evidence the agent writes itself.** Verdicts, approvals, manifests, progress and fallback JSON files are plain files the agent can create, edit or omit. Today's demo failures (footer, Rich Text, images) all passed through a check that read an agent-written or agent-shaped file.
2. **The control loop is mechanically fragile.** The stop hook can time out, can loop on things only a human can fix, and its failure order sends the agent to the wrong problem first.
3. **The instructions are too big and contradict themselves.** ~55–60k tokens of skills per run plus ~8–11k tokens of always-on rules, with the same rule copied in several places and drifted. When two instructions disagree, the agent picks one — and the gate may enforce the other.

## Recommended order of work

1. **Stop the bleeding (small, mechanical):** hook mode runs a fast gate (build `--quick`, cached link-audit, timeouts) — 2.1; reorder checks — 2.2; require all verdicts — 1.2; SVG fix — 5.2; untrack `.active-run.json` / tmp files / build artefacts and commit `.githooks/` with deps-check verifying the file — 5.6 + hygiene; fix `resume-demo` listing.
2. **Provenance (the big one):** verdicts with url + ref hash + build fingerprint; `run-gate approve` with plan hashing; read manifests, partial designs and placements from Sitecore/Edge only; BLOCKED via a script log. This closes most of section 1.
3. **Close the image pipeline gap properly:** one image path — section capture → manifest keyed by live URL + page + section → upload → `attach-images`. Retire content-map/download-images/content-extractor for the transcript flow (or make one producer), merge manifests instead of overwriting.
4. **Shrink and de-duplicate instructions:** one source per rule (rules live once, others link), split sitecore-build-demo's legacy flow out of the pipeline, a ≤150-line CLAUDE.md/root rule that is harness-aware, glob-scope the starter rules to `examples/**`, add `.claude/skills` parity and a Claude-Code stop-hook adapter.
5. **Turn prose-only rules into checks** using the site walk link-audit already does: page-local Data, display names, navigation filters, datasources under site Data.
6. **Human-in-the-loop channel:** `awaitingSE: "<question>"` honoured by the hook and shown in the hand-over, plus SE-acknowledged waivers keyed by diff hash — so legitimate dead ends stop instead of being gamed.
